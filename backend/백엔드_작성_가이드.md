# 백엔드 작성 가이드 (majunggil/backend)

뼈대의 `NotImplementedError` 와 `TODO` 를 실제 코드로 바꿀 때 지키는 규칙과 순서를 정리한 문서다.
설계 근거는 `../../doc/요구사항/백엔드 설계서_v2.4.md`, 응답 형식은 `API 명세서_v1.3.md`, 칼럼은 `테이블 정의서_v1.1.md` 를 본다. 이 문서와 설계서가 다르면 설계서가 맞다.

## 목차

| 장 | 내용 |
|---|---|
| 1 | 시작 전 준비 (환경, 패치, DB) |
| 2 | 계층 규칙 (어디에 무엇을 쓰는가) |
| 3 | 구현 순서와 단계별 완료 기준 |

## 1. 시작 전 준비

### 1.1 환경

```bash
cd majunggil/backend
py -3.12 -m venv .venv            # 또는 uv venv -p 3.12 .venv
.venv\Scripts\activate             # macOS, Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
copy .env.example .env             # macOS, Linux: cp .env.example .env
uvicorn app.main:app --reload --port 8000
```

- Python 은 3.12 로 맞춘다. 3.14 는 pydantic-core 설치가 실패할 수 있다.
- `.env` 의 `ADMIN_KEY` 에 32자 이상 값을 넣는다. 비어 있으면 관리자 API 는 항상 401 이다.
- `.env` 는 커밋하지 않는다 (`.gitignore` 에 들어 있다).

### 1.2 패치 적용 (DDL, 시드, DTO)

테이블 DDL, 시드, DTO 필드는 문서로 이미 정해져 있어서 `patches/` 에 준비돼 있다. 구현 전에 적용한다.

```bash
cd majunggil
git apply --check patches/01_ddl_seed.patch
git apply patches/01_ddl_seed.patch
git apply patches/02_schemas.patch
cd backend && pytest && ruff check app scripts tests
```

자세한 확인과 되돌리기 방법은 `../patches/README.md` 에 있다.

### 1.3 DB 띄우기

```bash
cd majunggil
docker compose up -d majunggil-db
```

- 첫 기동 때 `infra/db-init/01_roles.sql` 이 앱 계정(`majunggil_app`)을 만들고 시간대를 UTC 로 고정한다.
- 마이그레이션, 시드는 소유자 계정(`MIGRATION_DATABASE_URL`)으로, 앱 실행은 앱 계정(`DATABASE_URL`)으로 접속한다. 앱 계정에는 DDL 권한이 없다.

## 2. 계층 규칙

### 2.1 계층별로 쓰는 것과 쓰지 않는 것

| 계층 | 폴더 | 쓰는 것 | 쓰지 않는 것 |
|---|---|---|---|
| Presentation | `api/`, `schemas/` | URL, 쿼리, 경로 변수, Pydantic 형식 검증, 응답 모델, 캐시 헤더, ETag 비교, 관리자 키 의존성 | 업무 규칙, SQL |
| Application | `services/` | 유스케이스 흐름, 트랜잭션 경계(`read_tx`, `write_tx`), 존재 확인(404), 소속 검사, 버전 검사(409), 감사 로그 | `Request`, `Response` 같은 HTTP 객체 |
| Domain | `domain/` | 순수 함수: 카메라, 높이, 내비 목적지, 도보 시간, 단계 검사 | DB, HTTP, `datetime.now()` 직접 호출 (시각은 인자로 받는다) |
| Infrastructure | `repositories/` | SQL 실행, 파라미터 바인딩, `ST_AsGeoJSON` 변환, `camera_*` 칼럼 3개를 `camera` 객체로 묶기 | 업무 규칙 (거리 30m 초과면 거부 같은 판단) |
| 공용 | `core/`, `config.py`, `db.py` | 오류 형식, 로그, 보안 도구, 설정, 연결 풀 | 특정 화면, 특정 API 전용 코드 |

### 2.2 의존 방향

```
api ──▶ services ──▶ domain
            │
            └──────▶ repositories ──▶ DB
```

- `domain` 은 아무것도 import 하지 않는다 (표준 라이브러리만).
- `api` 는 `repositories` 를 직접 부르지 않는다. 항상 서비스를 거친다.
- 저장소 함수는 첫 인자로 `conn: Connection` 을 받는다. 트랜잭션은 서비스가 열어서 넘긴다.
- 서비스 메서드 하나가 트랜잭션 하나다. 한 요청 안에서 `read_tx()` 를 두 번 열지 않는다 (같은 시점 데이터 보장).

### 2.3 판단이 어려울 때

| 질문 | 답 |
|---|---|
| "주차장이 그 장소 소속인가" 검사는 어디에? | 서비스. 저장소는 소속 장소 id 만 돌려준다 (`parking_lot_place`) |
| "거리 30m 이하" 는 어디에? | 거리 계산 SQL 은 저장소(`distances_from_path`), 30m 비교는 서비스(`MAX_DISTANCE_FROM_PATH_M`) |
| 카메라 기본값 계산은? | 도메인(`camera.py`). 서비스가 DB 에서 읽은 좌표를 넘겨 부른다 |
| `Cache-Control` 헤더는? | 라우터(`api/`). 서비스는 헤더를 모른다 |
| 404 는 어디서 던지나? | 서비스. 저장소는 없으면 `None` 을 돌려준다 |

## 4. 파일별 작성 지침

### 4.1 `db.py`

| 할 일 | 내용 |
|---|---|
| `NAMING_CONVENTION` | 설계서 2.1.5 규칙: `pk_{테이블}`, `fk_{테이블}_{칼럼}`, `uq_{테이블}_{칼럼들}`, `ix_{테이블}_{칼럼들}`, `ck_{테이블}_{규칙}`. `migrations/*.sql` 의 제약 이름과 같아야 한다 (01 패치에 들어 있다) |
| `get_engine()` | 한 번만 만들고 재사용 (`lru_cache` 또는 모듈 변수). `pool_size`, `max_overflow`, `pool_timeout` 은 `config.py` 값. 접속 옵션으로 `timezone=UTC` |
| `reset_engine()` | 만들어 둔 엔진을 `dispose()` 하고 지운다. 테스트에서 URL 을 바꿀 때 쓴다 |
| `read_tx()` | `BEGIN` → `SET TRANSACTION READ ONLY` → `SET LOCAL statement_timeout` |
| `write_tx()` | `BEGIN` → `SET LOCAL statement_timeout`(관리자용 5초), `SET LOCAL lock_timeout`(3초). 예외가 나면 전체 롤백 |

```python
@contextmanager
def read_tx() -> Iterator[Connection]:
    s = get_settings()
    with get_engine().connect() as conn, conn.begin():
        conn.execute(text("SET TRANSACTION READ ONLY"))
        conn.execute(text(f"SET LOCAL statement_timeout = {int(s.DB_STATEMENT_TIMEOUT_MS)}"))
        yield conn
```

`SET LOCAL` 값은 바인딩 파라미터(`:x`)를 받지 않는다. 그래서 `int()` 로 감싼 설정값만 문자열에 넣는다. 사용자 입력은 절대 이 방식으로 넣지 않는다.

### 4.2 `repositories/tables.py`

- ORM 클래스 없이 SQLAlchemy Core `Table` 로만 정의한다 (ADR-004).
- 칼럼 이름, 타입, NULL 허용은 `migrations/001_init.sql`, `002_walk_network.sql` 과 한 글자도 다르지 않게 쓴다.
- 공간 칼럼은 GeoAlchemy2 `Geometry("POINT", srid=4326)` 처럼 기하 종류와 SRID 를 적는다.
- 다 쓰면 `tests/integration/test_schema.py` 로 실제 DB 와 비교한다.

### 4.3 `repositories/geo_sql.py`

공간 SQL 조각을 한곳에 모아 geography 변환을 빠뜨리지 않게 한다. 저장소 파일에서 `func.ST_...` 를 직접 쓰지 말고 여기 함수를 쓴다.

| 함수 | 만들 SQL |
|---|---|
| `as_geojson(col, label)` | `ST_AsGeoJSON(col, 6)` 에 `label` |
| `lng(col)`, `lat(col)` | `round(ST_X(col)::numeric, 6)`, `ST_Y` 동일 |
| `length_m(col)` | `ST_Length(col::geography)` (미터) |
| `make_point(lng, lat)` | `ST_SetSRID(ST_MakePoint(lng, lat), 4326)` |
| `parse(text)` | `json.loads`, `None` 이면 `None` |
| `camera_of(row)` | `camera_bearing`, `camera_pitch`, `camera_zoom` 셋 다 NULL 이면 `None`, 아니면 `{"bearing", "pitch", "zoom"}` |

거리, 길이는 항상 `::geography` 로 계산한다. geometry(4326) 그대로 재면 단위가 "도" 라서 값이 0.0003 같은 숫자로 나온다.

### 4.4 나머지 저장소 (`place_repo`, `building_repo`, `walk_route_repo`)

- 돌려주는 값은 `dict` 또는 `list[dict]` 다 (`.mappings().all()`). DTO 로 바꾸는 일은 서비스가 한다.
- 없으면 `None`, 예외를 던지지 않는다.
- 목록은 항상 `ORDER BY` 를 붙인다 (주차장 `priority, id`, 단계 `step_order`). 순서가 없으면 테스트가 가끔 깨진다.
- 검색(`search_places`)은 `ILIKE` 에 `%` 와 `_` 를 이스케이프한 검색어를 넣는다. 전체 개수와 목록을 같은 조건으로 센다.
- `walk_route_repo` 의 쓰기 함수는 관리자 서비스만 부른다. 잠금 순서는 항상 `walk_route` → `walk_route_step`.
- `touch_route` 는 `now()` 가 아니라 `clock_timestamp()` 로 버전을 올린다 (설계서 2.7.4).
- `version_info` 는 `extract(epoch from max(updated_at)) * 1e6` 을 정수로 돌려준다 (ETag 재료).

### 4.5 `domain/*`

설계서 2.4.5 에 알고리즘이 의사 코드로 있다. 그대로 옮기고 단위 테스트를 같이 쓴다.

| 파일 | 함수 | 규칙 요약 |
|---|---|---|
| `geo.py` | `azimuth_deg(a, b)` | 구면 방위각, 북 0도, 시계 방향, 0 이상 360 미만. 같은 점이면 `None` |
| `building.py` | `render_height` | `height_m > 0` 이면 소수 1자리, 아니면 `floor_count * 3.0`, 둘 다 없으면 6.0 |
| `navigation.py` | `select_navigation_target` | `(priority, id)` 가 가장 작은 주차장. 빈 목록이면 `DataIntegrityError` |
| `navigation.py` | `walk_time_min` | 저장값 우선, 없으면 `max(1, ceil(distance_m / 67))` |
| `camera.py` | `place_camera`, `parking_camera`, `step_cameras` | 저장값 우선. 없으면 방위각 계산 + 기본 pitch, zoom. 계산값에는 `camera_is_default=True` |
| `steps.py` | `clean_instruction`, `check_instruction`, `check_steps` | 개수 2~30, 순서 1..n, 문장 1~200자. 위반을 모두 모아 한 번에 돌려준다 |
| `attribution.py` | `attributions` | 출처 값을 중복 없이 고정 순서로 표기 문자열로. 건물이 없으면 `["직접 조사"]`. 표기 문구는 [검증 필요: ODbL 등 각 출처 표기 조건] |

`camera.py`, `navigation.py`, `steps.py` 의 `@dataclass` 는 필드가 비어 있다. 필드는 설계서 2.4.3, 2.4.5 에 맞춰 직접 정한다 (예: `Camera(bearing: float, pitch: float, zoom: float)`, `Violation(field: str, reason: str, message: str)`).

`azimuth_deg` 예시:

```python
import math

def azimuth_deg(a: Lnglat, b: Lnglat) -> float | None:
    if a == b:
        return None
    lng1, lat1, lng2, lat2 = map(math.radians, (*a, *b))
    d = lng2 - lng1
    x = math.sin(d) * math.cos(lat2)
    y = math.cos(lat1) * math.sin(lat2) - math.sin(lat1) * math.cos(lat2) * math.cos(d)
    return (math.degrees(math.atan2(x, y)) + 360) % 360
```

같은 두 점으로 SQL `degrees(ST_Azimuth(a::geography, b::geography))` 결과와 비교하는 통합 테스트를 하나 둔다. 소수 첫째 자리까지 같으면 통과로 본다 (추정: 구면과 타원체 차이로 아주 작은 오차가 날 수 있다).

### 4.6 `schemas/*`

- 02 패치를 적용하면 필드가 채워진다. 새 필드를 추가할 때는 API 명세서를 먼저 고치고 그다음 코드를 고친다.
- 입력 DTO 는 모두 `InModel` 을 상속한다 (`extra="forbid"`, `str_strip_whitespace=True`).
- 응답 필드 이름은 DB 칼럼과 같은 snake_case 다. 프론트도 그대로 쓴다.
- 시각은 `iso_seconds`(초 단위), 경로 버전 `updated_at` 만 `iso_micros`(마이크로초). 버전을 초 단위로 내리면 프론트 저장이 항상 409 가 된다.
- `StepPatchIn` 은 "키 없음" 과 "null" 을 구분해야 한다. `body.model_fields_set` 에 있는 키만 바꾼다.

### 4.7 `services/*`

서비스 메서드 기본 모양:

```python
def detail(self, place_id: int) -> PlaceDetail:
    with read_tx() as conn:
        row = place_repo.get_place(conn, place_id)
        if row is None:
            raise not_found("place")
        entrances = place_repo.list_entrances(conn, place_id)
        lots = place_repo.list_parking_lots(conn, place_id)
        landmarks = place_repo.list_landmarks(conn, place_id)
        sources = building_repo.list_sources(conn, place_id)
    # 트랜잭션 밖: 도메인 계산과 DTO 조립
    ...
    return PlaceDetail(...)
```

| 서비스 | 주의할 점 |
|---|---|
| `PlaceService.search` | `q` 가 없으면 전체 목록. `total` 은 limit, offset 적용 전 개수 |
| `PlaceService.detail` | `navigation_target` 은 `select_navigation_target`, `arrival_radius_m` 이 NULL 이면 `DEFAULT_ARRIVAL_RADIUS_M` |
| `BuildingService.list_for_place` | 장소가 없으면 404. 건물이 0개면 빈 `features` + `["직접 조사"]` |
| `WalkRouteService.list_for_place` | `parking_lot_id` 가 다른 장소 소속이면 400 (`parking_lot_place` 로 확인). ETag 가 맞으면 본문 없이 `not_modified=True` 같은 결과를 돌려주고 304 는 라우터가 만든다 |
| `AdminWalkRouteService.replace_steps` | 설계서 2.4.5 (5) 순서를 그대로: DB 없는 검사(1~4) → `write_tx` → 잠금 → 버전 비교(409) → 랜드마크 소속 → 경로와 거리 30m → 건물 안 지점 → 삭제, 삽입 → `touch_route` → 감사 로그 |
| `AdminWalkRouteService.patch_step` | `expected_updated_at` 이 있을 때만 버전 비교. 바꾼 뒤에도 경로 버전을 올린다 |

감사 로그에는 경로 id, 단계 수, `updated_by`, `request_id` 만 남긴다. 단계 문장 원문, 관리자 키, IP 는 남기지 않는다 (설계서 2.7.3).

### 4.8 `api/*`

- 라우터는 서비스를 부르고 헤더를 붙이는 일만 한다. 10줄을 넘으면 서비스로 옮길 것이 있는지 본다.
- `response_model` 을 붙여 Swagger 에 응답 모양이 보이게 한다.
- 캐시 헤더는 엔드포인트마다 정해져 있다.

| 엔드포인트 | `Cache-Control` | 그 밖 |
|---|---|---|
| `GET /places`, `GET /places/{id}` | `public, max-age=60` | |
| `GET /places/{id}/buildings` | `public, max-age=300` | `Content-Type: application/geo+json` |
| `GET /places/{id}/walk-routes` | `no-cache` | `ETag`. `If-None-Match` 가 같으면 304 (본문 없음, 같은 ETag 헤더) |
| `/admin/*` | `no-store` | `require_admin` 의존성 (라우터에 이미 붙어 있음) |
| `/health` | `no-store` | DB 실패 시 503 `{"status": "error", "db": "unavailable"}` |

```python
@router.get("/{id}/walk-routes", response_model=WalkRouteListOut, responses={304: {"description": "변경 없음"}})
def list_walk_routes(id: int = Path(ge=1), parking_lot_id: int | None = Query(default=None, ge=1),
                     if_none_match: str | None = Header(default=None, alias="If-None-Match")):
    r = WalkRouteService().list_for_place(id, parking_lot_id, if_none_match)
    headers = {"Cache-Control": "no-cache", "ETag": r.etag}
    if r.not_modified:
        return Response(status_code=304, headers=headers)
    return JSONResponse(r.body.model_dump(mode="json"), headers=headers)
```

`RoutesResult` 의 필드(`etag`, `not_modified`, `body` 등)는 위처럼 쓰기 편하게 직접 정한다.

### 4.9 `core/*`, `api/deps.py`, `main.py`

| 파일 | 할 일 |
|---|---|
| `core/errors.py` | `invalid(field, reason, message)` 는 `AppError("INVALID_INPUT", ..., details=[{field, reason, message}])` 를 돌려준다. `not_found(what)` 도 같은 방식. 호출하는 쪽에서 `raise invalid(...)`. DB 연결 실패, 시간 초과(`OperationalError`)는 503 + `Retry-After`, 나머지 예외는 500 (로그에 접속 문자열을 가린다) |
| `core/security.py` | `key_matches` 는 `hmac.compare_digest`. 기대값이 비어 있으면 항상 `False`. 제한기는 `clock` 인자를 받아 테스트에서 시간을 흉내 낸다 |
| `api/deps.py` | `client_ip` 는 `request.client.host`. 앱은 `X-Forwarded-For` 를 직접 읽지 않는다. 프록시를 믿을 범위는 uvicorn 이 환경 변수 `FORWARDED_ALLOW_IPS` 로 정한다 (기본 127.0.0.1, `"*"` 금지). `require_admin` 은 잠김 → 429, 키 틀림 → 실패 기록 후 401, 맞음 → 계수 초기화 |
| `api/admin_route.py` | 이미 있다. `AdminRoute` 가 관리자 라우트마다 본문 해석 전에 `require_admin` 을 부른다. 관리자 라우터 `dependencies` 에 `Depends(require_admin)` 을 다시 넣지 않는다 (실패 횟수가 두 번 세어진다). 라우터의 `Security(APIKeyHeader(...))` 는 Swagger 입력칸 표시용이라 지우지 않는다 |
| `core/logging.py` | JSON 한 줄 로그. 남기지 않는 것: 쿼리 문자열, 요청 본문, `X-Admin-Key`, IP, 단계 문장 |
| `main.py` | 미들웨어 순서(바깥 → 안): request_id + 접근 로그 + 보안 헤더 → 본문 크기 `MAX_BODY_BYTES`(413), `application/json` 확인(415) → 요청 횟수(429). CORS 는 `ALLOWED_ORIGINS` 가 있을 때만. Content-Length 는 `int()` 로 바로 바꾸지 말고 `core/http.py` 의 `declared_length()` 를 쓴다: `None`(정수 아님, 음수)이면 400 `INVALID_INPUT` (`field: header.Content-Length`, `reason: invalid_type`). 운영에서 32자 미만 `ADMIN_KEY` 면 시작하지 않는 검사는 이미 `create_app` 에 있다 |

## 6. 오류 처리 규칙

- 오류 응답은 항상 `{"error": {code, message, request_id, timestamp, details}}` 한 가지 모양이다. 직접 `JSONResponse` 로 오류를 만들지 말고 `AppError` 를 던진다.
- 입력 오류의 `details[].reason` 은 API 명세서 1.11 의 reason 표 값만 쓴다 (`required`, `too_long`, `out_of_range`, `step_order`, `landmark`, `location`, `inside_building` 등).
- 단계 저장 검사는 첫 위반에서 멈추지 않고 모두 모아 `details` 에 담는다 (API 명세서 3.7).
- `message` 는 사용자가 읽는 한국어 문장이다. 내부 정보(SQL, 파일 경로, 접속 문자열)를 넣지 않는다.

| 상황 | 코드 | 상태 |
|---|---|---|
| 형식 오류, 규칙 위반 | `INVALID_INPUT` | 400 |
| 관리자 키 없음, 틀림 | `UNAUTHORIZED` | 401 |
| 없는 장소, 경로, 단계 | `NOT_FOUND` | 404 |
| 버전 다름 | `CONFLICT` | 409 |
| 본문 64KB 초과 | `PAYLOAD_TOO_LARGE` | 413 |
| JSON 이 아닌 본문 | `UNSUPPORTED_MEDIA` | 415 |
| 요청 과다, 키 잠김 | `RATE_LIMITED` | 429 + `Retry-After` |
| DB 연결 실패, 시간 초과 | `SERVICE_UNAVAILABLE` | 503 + `Retry-After` |
| 그 밖 | `INTERNAL` | 500 |

## 11. 자주 하는 실수

| 실수 | 증상 | 바로잡기 |
|---|---|---|
| geometry 로 거리 계산 | 거리가 0.0003 같은 값 | `::geography` 변환 (`geo_sql.length_m`) |
| 좌표 순서 `[위도, 경도]` | 지도에서 바다 한가운데 | 항상 `[경도, 위도]` (GeoJSON 규칙) |
| 버전을 `now()` 로 갱신 | 같은 트랜잭션 안 두 번 저장 시 버전 같음 | `clock_timestamp()` |
| 버전을 초 단위로 응답 | 프론트 저장이 항상 409 | `iso_micros` |
| 라우터에서 `read_tx` 사용 | 계층 섞임, 테스트 어려움 | 서비스로 옮김 |
| `ORDER BY` 빠짐 | 테스트가 가끔 실패 | 목록 SQL 에 항상 정렬 |
| 문자열로 SQL 조립 | SQL 주입 위험 | `select()` 또는 `text()` + 바인딩 파라미터 |
| 랜드마크 이름만 바꾸고 경로 버전 그대로 | 브라우저가 옛 이름을 계속 보여줌 | `load_seed` 에서 그 장소 경로 `updated_at` 갱신 |
| 앱 계정으로 마이그레이션 | 권한 오류 | `MIGRATION_DATABASE_URL` 사용 |
| 관리자 라우터에 `Depends(require_admin)` 추가 | 키 없이 깨진 JSON 이 400, 실패 횟수 두 번 | `AdminRoute` 만 쓴다 |
| `int(request.headers["content-length"])` | `Content-Length: abc` 에 500 | `declared_length()` |
| uvicorn `--forwarded-allow-ips "*"` | `X-Forwarded-For` 위조로 잠금, 요청 제한 우회 | 기본값(127.0.0.1), 프록시 뒤에서만 `FORWARDED_ALLOW_IPS=<프록시 IP>` |
